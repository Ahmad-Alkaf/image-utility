## Architecture notes

- **Tool registry.** `src/lib/constants.ts` `TOOLS` holds every tool's id, names, descriptions, and flags. Pages, the header, the footer, the sidebar, and the cards all read from it. Change text there, not in the components.
- **Server tools** (`convert`, `compress`, `resize`, `filters`, `watermark`, `metadata`) are thin route files that call `createProcessHandler` in `src/lib/process-route.ts`. The helper does auth, rate limiting, validation, storage, the `ProcessingJob` row, and error mapping. Throw `ProcessingError` (`src/lib/processing/errors.ts`) for a message the user may see; anything else becomes a generic 500.
- **Background removal** runs entirely in the browser (`src/workers/remove-bg.worker.ts`). It creates no job row and uploads nothing. `next.config.ts` sends COEP/COOP headers for it; keep them.
- **Storage** (`src/lib/storage.ts`) is local disk in `STORAGE_DIR` (default `.storage`, `/app/.storage` in Docker) unless the S3 keys are set.
- **Retention.** `src/instrumentation.ts` starts `startCleanupScheduler()` once per server start. Every hour it deletes files older than `FILE_RETENTION_HOURS` (24) and sets `filesDeletedAt` on the job row. Rows are kept for the dashboard history and the public counters. `POST /api/cron/cleanup` (Bearer `CRON_SECRET`) runs it on demand.
- **Database.** Prisma 7 with the `prisma-client-js` generator into `src/generated/prisma` (git-ignored, regenerated by `npm run build`). Migrations live in `prisma/migrations`; the Docker entrypoint runs `prisma migrate deploy` on start. After a schema change run `npx prisma migrate dev --name <change>`.
- **Tests.** `npm test` runs Vitest on `__tests__/` (tool registry, errors, validation, format helpers, rate limiter). The process route helper is not unit-tested; it needs Clerk, Prisma, and storage.
- **Deploy.** Coolify with the `Dockerfile`. Steps are in `README.md`; the org-level checklist is in `../kaflabs/DEPLOY-PLAN.md`.
- Clerk v7 uses `NEXT_PUBLIC_CLERK_SIGN_IN_FALLBACK_REDIRECT_URL` (not the old `AFTER_SIGN_IN_URL` names).
